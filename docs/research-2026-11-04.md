# Why SQL SlotCheck

The research window was November 4 in America/Chicago, from 06:00 UTC November 4 to 06:00 UTC November 5. The project selection uses observations inside that interval.

At 06:02:36 UTC on November 4, an auto-ontology user reported losing values from SQL joins when an adapter converted duplicate column names into dictionary keys. The reporter supplied a SQLite reproduction, described distinct outcomes for three connectors, and showed why constructing a test frame downstream missed the corruption. These database-specific results are the reporter's observations. SlotCheck independently exercises the conversion error with its own queries on SQLite. [Issue #408](https://github.com/NVIDIA/auto-ontology/issues/408) · [Affected SQLite code at the reported revision](https://github.com/NVIDIA/auto-ontology/blob/caced11e69e19663dfa0f73778dbecbcb71e87a0/auto_ontology/connectors/sqlite.py#L134-L136)

Our saved November 4 snapshot of GitHub Trending at 17:14 UTC placed auto-ontology first, Floci fourth and Spec Kit seventh. An earlier community archive at 08:42 UTC had Floci eighth. The November 5 observation at 14:00 UTC again showed auto-ontology first. These are three separate readings of a rolling list. They do not establish a full-day rank or a historical star gain. The five tracked projects had zero net star or fork change between their first observed baselines and the November 5 observation. None had an open issue or pull request. That left no measured portfolio leader, so the choice favored a reproducible defect, an identifiable audience and a low-cost demo.

## Existing SQL testing tools

SQLFluff can flag duplicate aliases before a query runs. SQLAlchemy supports result tuples carrying repeated labels. Pandera can validate data and column order when given expectations. DB-API and ADBC conformance suites cover a broader driver interface, and sqllogictest checks SQL engine results. A user could build equivalent tests in several of these tools. SlotCheck packages six ready-to-run cases for the conversion between a driver and an application's final result. [SQLFluff AL08](https://docs.sqlfluff.com/en/3.3.0/reference/rules.html#rule-aliasing-unique-column) · [SQLAlchemy result semantics](https://docs.sqlalchemy.org/en/21/changelog/migration_14.html#select-objects-and-derived-from-clauses-allow-for-duplicate-columns-and-column-labels) · [Pandera](https://pandera.readthedocs.io/en/stable/dataframe_schemas.html) · [ADBC validation](https://github.com/adbc-drivers/validation) · [sqllogictest](https://www.sqlite.org/sqllogictest/doc/trunk/about.wiki)

The DB-API exposes ordered metadata via cursor.description, and SQLite supplies it for a SELECT even when the result contains zero rows. The example uses these documented interfaces. [PEP 249](https://peps.python.org/pep-0249/#description) · [Python sqlite3 documentation](https://docs.python.org/3/library/sqlite3.html#sqlite3.Cursor.description)
